# 3. 포트 포워딩

[← 가이드 목차](README.md)

## 한 줄 요약

포트 포워딩은 **SSH 연결을 "비밀 통로"로 써서, 원래는 직접 닿을 수 없는 곳에 접속하는 기능**입니다. 서버 방화벽에 SSH 포트(예: 22, 6622)만 열려 있어도, 그 통로로 DB나 웹 같은 다른 서비스까지 쓸 수 있습니다.

## 어떤 종류를 고를까요?

| 하고 싶은 것 | 선택 |
| --- | --- |
| 서버(또는 서버 뒤)의 DB·웹·관리 페이지를 **내 PC 프로그램**으로 쓰기 | **L 로컬** — 가장 많이 씀 |
| **서버 쪽 네트워크**로 브라우저 전체를 쓰기 | **D SOCKS** |
| **내 PC의 서비스**를 서버에서 부르기 | **R 원격** |

## 설정하는 곳

1. 사이드바에서 세션에 마우스를 올리고 ✏️(편집)를 누릅니다.
2. 아래쪽 **포트 포워딩**에서 **추가**를 누릅니다.
3. 한 줄에 하나씩 설정합니다.

   ```text
   [종류 ▾] [포트]  [대상 호스트]  [대상 포트]  [🗑]
   ```

4. **저장**한 뒤 세션에 접속합니다.

포워딩은 **접속할 때 시작**되고 **탭을 닫으면 끝납니다**. 설정을 바꿨다면 탭을 다시 연결해야 적용됩니다.

접속하면 터미널 첫 부분에 결과가 표시됩니다.

```text
⇄ 포트 포워딩 L 127.0.0.1:13306 → localhost:3306 (서버 기준)     ← 성공
⚠ 포트 포워딩 실패 L 127.0.0.1:13306 → …: 이유                   ← 실패
```

포워딩이 실패해도 터미널 연결은 그대로 유지됩니다.

---

## ① L 로컬 — 서버 쪽 서비스를 내 PC에서 쓰기

**언제 쓰나요?** 서버나 서버 뒤쪽에 있는 서비스를 내 PC 프로그램으로 쓰고 싶을 때입니다.

```text
[내 PC 프로그램] → 127.0.0.1:13306 ══SSH 통로══▶ [서버] → localhost:3306 (MySQL)
```

### 예시 1: 서버의 MySQL을 내 PC의 DB 프로그램으로 쓰기

서버에 MySQL(3306)이 있는데 외부에는 열려 있지 않은 경우입니다.

| 종류 | 포트 (이 PC) | 대상 호스트 | 대상 포트 |
| --- | --- | --- | --- |
| L 로컬 | `13306` | `localhost` | `3306` |

1. 저장하고 접속합니다.
2. DBeaver, HeidiSQL 같은 DB 프로그램에서 접속 주소를 **`127.0.0.1`**, 포트를 **`13306`**으로 입력합니다.
3. 내 PC에 접속한 것처럼 보이지만, 실제로는 서버의 MySQL에 연결됩니다.

### 예시 2: 서버에서만 열리는 관리 웹페이지 보기

| 종류 | 포트 (이 PC) | 대상 호스트 | 대상 포트 |
| --- | --- | --- | --- |
| L 로컬 | `8080` | `localhost` | `8080` |

브라우저에서 `http://localhost:8080`을 엽니다.

### 예시 3: 서버 옆의 다른 내부 장비에 접속하기

서버와 같은 내부망에 있는 `192.168.0.50`의 PostgreSQL(5432)에 접속하는 경우입니다.

| 종류 | 포트 (이 PC) | 대상 호스트 | 대상 포트 |
| --- | --- | --- | --- |
| L 로컬 | `15432` | `192.168.0.50` | `5432` |

> 💡 L의 **대상 호스트는 "서버 입장에서 본" 주소**입니다. `localhost`는 서버 자신을, `192.168.0.50`은 서버에서 보이는 다른 장비를 뜻합니다.

## ② D SOCKS — 서버 쪽 네트워크로 웹 서핑하기

**언제 쓰나요?** 서버가 있는 내부망의 **여러 웹페이지를 브라우저로** 보고 싶을 때입니다. L로 하나씩 등록하기 번거로울 때 편합니다.

```text
[브라우저] → SOCKS5 127.0.0.1:1080 ══SSH 통로══▶ [서버] → 어디든 (서버가 접속 가능한 곳)
```

| 종류 | 포트 (이 PC) |
| --- | --- |
| D SOCKS | `1080` |

1. 저장하고 접속합니다. 터미널에 `⇄ 포트 포워딩 D SOCKS5 127.0.0.1:1080`이 표시됩니다.
2. 브라우저의 프록시를 **SOCKS5, 호스트 `127.0.0.1`, 포트 `1080`**으로 설정합니다.
   - Firefox: 설정 → 일반 → 네트워크 설정 → **수동 프록시 설정** → SOCKS 호스트 `127.0.0.1`, 포트 `1080`, **SOCKS v5** 선택
3. 이제 브라우저는 서버에서 접속하는 것처럼 동작합니다. 서버 내부망 주소도 열립니다.

> 💡 다 쓰고 나면 브라우저 프록시 설정을 원래대로 돌려놓으세요. WLT 탭을 닫으면 프록시가 꺼지므로 인터넷이 안 되는 것처럼 보일 수 있습니다.

## ③ R 원격 — 내 PC의 서비스를 서버에서 부르기

**언제 쓰나요?** L과 반대 방향입니다. **내 PC에서 실행 중인 것**을 서버 쪽에서 접속해야 할 때 씁니다.

```text
[서버 프로그램] → 서버의 localhost:9000 ══SSH 통로══▶ [내 PC] → localhost:3000 (개발 서버)
```

### 예시: 내 PC의 개발 서버를 서버에서 호출해 보기

내 PC에서 개발 중인 웹서버가 3000번 포트로 실행 중인 경우입니다.

| 종류 | 포트 (서버) | 대상 호스트 | 대상 포트 |
| --- | --- | --- | --- |
| R 원격 | `9000` | `localhost` | `3000` |

서버 터미널에서 아래 명령을 실행하면 **내 PC의 3000번**이 응답합니다.

```bash
curl http://localhost:9000
```

> 💡 R의 **포트는 서버에서 열리는 포트**이고, **대상 호스트는 "내 PC 입장에서 본" 주소**입니다.

## 안 될 때 확인할 것

| 증상 | 원인과 해결 |
| --- | --- |
| `⚠ 포트 포워딩 실패 … Only one usage of each socket address` 등 | 내 PC에서 그 포트를 이미 다른 프로그램이 쓰고 있습니다. `13306`, `18080`처럼 겹치지 않는 번호로 바꾸세요. |
| `⚠ 포트 포워딩 실패 … server refused` (R) | 서버가 원격 포워딩을 막아 두었거나 그 포트가 사용 중입니다. |
| 포워딩은 성공했는데 접속하면 바로 끊김 | 서버 SSH 설정에서 포워딩을 막아 두었을 수 있습니다(`/etc/ssh/sshd_config`의 `AllowTcpForwarding no`). 서버 관리자에게 확인하세요. 대상 호스트·포트가 맞는지도 확인하세요. |
| 설정을 바꿨는데 그대로임 | 포워딩은 접속할 때 시작됩니다. 탭을 닫고 다시 접속하거나, 탭 우클릭 → **다시 연결**을 누르세요. |
| 같은 사무실의 다른 PC에서 접속이 안 됨 | 보안을 위해 L·D는 내 PC 안(`127.0.0.1`)에서만, R은 서버 안(`localhost`)에서만 열립니다. 다른 PC에서는 쓸 수 없습니다. |

## 참고

- 한 세션에 포워딩을 여러 개 추가할 수 있습니다.
- D(SOCKS)는 인증 없는 SOCKS5 CONNECT 방식만 지원합니다. 대부분의 브라우저와 프로그램은 이 방식으로 동작합니다.
- OpenSSH 명령과 비교하면 아래와 같습니다.

  | WLT 설정 | 같은 OpenSSH 명령 |
  | --- | --- |
  | L `13306` → `localhost:3306` | `ssh -L 13306:localhost:3306 user@server` |
  | R `9000` → `localhost:3000` | `ssh -R 9000:localhost:3000 user@server` |
  | D `1080` | `ssh -D 1080 user@server` |
